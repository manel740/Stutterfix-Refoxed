# StutterFix

> ⚠️ **Warning:** This mod is prone to bugs. It's recommended to always keep a backup of your configuration and worlds before installing or updating it, and to test it on a separate instance first if possible.

StutterFix is a mod that allows you to configure the main threads of the game, giving you control over stuttering. By default, the mod already comes with an approximate configuration to reduce stuttering.

Version **0.1.8** introduced the ability to configure threads directly from the menu, adding a new option.

---

## Options Menu

There are five options available for configuration. In the descriptions, **N** represents the number of threads your processor supports.

| Option | Description |
|---|---|
| **Worker threads count** | Vanilla default: `N - 1`. StutterFix default: `N - 5`. This is the number of threads dedicated to tasks such as generating chunks. A lower value reduces CPU overhead (less stuttering) but slows down chunk generation speed. |
| **Priority cutoff point** | Sets the cutoff point for worker thread priority. The higher the value, the more threads (the first portion) will have normal priority, while fewer threads (the last portion) will have minimum priority. The value must be lower than the number of worker threads for a real cutoff to occur; otherwise, all threads will have normal priority. Threads with minimum priority help reduce stuttering. |
| **Render thread priority** | Priority of the rendering thread, where the client runs: the player, sound, inputs, and rendering. |
| **Server thread priority** | Only appears in singleplayer mode. In singleplayer, the game starts an integrated server that runs the entire world (ticks, entities, and initializing chunk generation, which is executed on the worker threads). |
| **Remove Yield()** | The rendering thread makes a call in each loop called `yield()`, whose function is to inform the "scheduler" that the current thread is willing to give up its use of the processor to other threads. Removing this call can make FPS more stable. |

> **Note:** The *Worker Threads Count* and *Priority cutoff point* options have little effect in multiplayer, since the world is generated by the server, so the client doesn't experience stuttering issues caused by world generation.

## Disabling the GUI (Version ≥ 0.2.3)

Inside the `config` folder in the `.minecraft` directory, there is a configuration file called `stutterfix-config.json`, which contains the `hide_gui` option.

- Set it to `true` to disable the game's interface.
- Set it to `false` if you want the interface back.

## Changelog

| Version | Changes |
|---|---|
| ≤ 0.1.5 | All worker threads had minimum priority, causing low responsiveness in chunk generation. |
| 0.1.6 | Worker threads were switched to normal priority to improve responsiveness. |
| 0.1.7 | The first half of worker threads were set to normal priority and the second half to minimum priority, aiming for a better balance between reducing stuttering and maintaining responsiveness during chunk generation. |
| 0.1.8 | Added the option in the menu to configure threads. Removed the `Thread.yield()` removal, as it was conflicting with other mods like VulkanMod. |
| 0.1.9 | Re-added the "remove yield()" option (it will not appear in the menu if you use VulkanMod). Improved tooltips. |
| 0.2.0 | Made changes to the GUI to resolve compatibility issues with some mods, such as Bedrockify. |

---

## Warnings

- The mod does **not** fix stuttering issues caused by the garbage collector. This can be reduced by using the `-XX:+UseShenandoahGC` flag and allocating more memory in the JVM arguments. Search for "JVM arguments for Minecraft" for more information.
